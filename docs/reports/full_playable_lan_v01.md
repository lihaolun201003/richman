## 3. 游戏规则

### 3.1 地图

36 格环形棋盘，`10×8` 网格布局（11 列 × 9 行含四角），四角位于索引 `0 / 10 / 18 / 28`：

| 索引 | 类型 | 名称 |
| --- | --- | --- |
| 0 | START | 城市广场 |
| 10 | JAIL | 看守所 |
| 18 | PARK | 中央公园 |
| 28 | GO_TO_JAIL | 治安巡查 |

其余 32 格为地产（24 处，含 2 处交通枢纽）、机遇（5 处）、税收（2 处）、奖金池（1 处）。

11 个片区：东城片区、星河商圈、云港湾区、高新园区、湖景片区、交通枢纽、
文创街区、金融区、未来城、学区、滨海新区。另有 1 处独立地产（山景社区）不参与垄断。

### 3.2 数值

| 项目 | 数值 |
| --- | --- |
| 初始资金 | 15,000 |
| 经过 / 停留起点 | +2,000 |
| 地产价格 | 1,200 ～ 6,000（合计 83,300） |
| 租金系数（Lv0→Lv3） | 0.06 / 0.34 / 0.78 / 1.45 × 地价 |
| 交通枢纽租金系数 | 0.08 / 0.44 / 1.00 / 1.80 × 地价 |
| 升级费用 | 0.50 / 0.80 / 1.20 × 地价 |
| 片区垄断 | 该区租金 ×2 |
| 保释金 | 1,500（最高关押 3 回合后强制付费） |
| 城市营业税 | 固定 1,200 |
| 奢侈消费税 | 总资产的 4%（最低 300） |
| 税金注入奖金池 | 税金的一半 |
| 初始奖金池 | 1,500 |
| 每人道具上限 | 5 张（开局发 2 张） |
| 一局上限 | 200 轮（超过按总资产判定胜者） |

### 3.3 回合流程

```
TURN_START  → 结算状态（跳过回合 / 保护期）
WAIT_ROLL   → 等待当前玩家掷骰（或看守所决策）
ROLLING     → 骰子演出（结果由 Host 生成）
MOVING      → 逐格移动（经过起点发奖励、撞上路障停下）
ARRIVED     → 落格
RESOLVE_TILE→ 结算：购买 / 升级 / 收租 / 机遇 / 税收 / 奖金池 / 押送看守所
WAIT_DECISION → 需要玩家选择时（购买、升级、选目标）
APPLY_EVENT → 应用机遇事件及其后续效果
TURN_END    → 清算负现金、状态计时、切换到下一玩家
```

### 3.4 破产

1. 需要付款但现金不足 → 进入债务流程；
2. 计算「现金 + 全部资产变卖值」能否覆盖欠款；
3. **能覆盖** → 按「先卖便宜的、等级低的」顺序变卖，付清为止（日志逐条展示）；
4. **不能覆盖** → 直接破产，**不再变卖**（避免白白损失三成回收率），
   现金与全部地产整体移交债权人；无债权人则归银行；
5. 破产者不再参与回合，棋子灰化，只剩 1 人时立即结算。

## 4. 网络架构

```
Host 进程                                   Client 进程
┌──────────────────────────────┐            ┌──────────────────────────────┐
│ 主线程 (pygame 循环)          │            │ 主线程 (pygame 循环)          │
│   GameEngine.update(dt)       │            │   渲染本地快照                │
│   state.revision++            │            │   把点击翻译成 Command        │
│   限流广播快照 (≥80ms)         │            │                              │
│         ▲          │          │            │         ▲          │          │
│  RemoteController  │ TcpConn  │   TCP      │  TcpConn  │        ▼          │
│         │          ▼          │  4B 长度    │         │   发送 COMMAND      │
│   Command 队列  发送线程      │  + JSON    │   接收线程           │          │
│         ▲          │          │◄──────────►│         │          │          │
│  接收线程 ─ 解析线程           │            │  STATE_SNAPSHOT 解析         │
└──────────────────────────────┘            └──────────────────────────────┘
```

- **传输**：TCP，消息格式 `4 字节大端长度 + UTF-8 JSON`。
  选择 JSON 而非 msgpack，是为了可读、可调试，且大富翁是低频同步，
  体积完全不是瓶颈；也避免了 pickle 的安全与兼容问题。
- **线程模型**：每条连接一对收发线程，主线程只做「入队 / 取队列」，绝不阻塞渲染。
- **版本校验**：所有消息携带 `protocol_version`，不一致直接拒绝连接并给出中文提示。
- **心跳**：Host 每 2 秒 PING，客户端立即 PONG，用于估算延迟与判活。
- **广播限流**：状态快照最小间隔 80ms，且只在 `revision` 变化时发送；
  发送前把事件日志裁剪到最近 40 条，单帧包体约 15–40 KB。
- **自动发现**：Host 每 1.5 秒向 `255.255.255.255` 与子网广播地址发送房间信息
  （房间名 / 端口 / 人数 / 阶段），客户端监听 28081 端口即可列出同网段房间。
  自动发现只是便利入口，**手动输入 IP 始终可用**。

## 5. Host / Client 权责

| 能力 | Host | Client |
| --- | --- | --- |
| 持有 `GameEngine` / 真实 `GameState` | ✅ 唯一 | ❌ 完全没有 |
| 生成骰子点数 | ✅ | ❌ |
| 决定最终位置 / 金额 / 租金 / 卡牌结果 / 胜负 | ✅ | ❌ |
| 校验并执行 `Command` | ✅ | ❌ |
| 广播状态快照 | ✅ | ❌ |
| 显示状态 | ✅ | ✅（只读快照） |
| 发送玩家意图 | ✅ | ✅ |
| 播放动画 / 音效 / hover | ✅ | ✅（纯本地表现） |

**已经用测试证明的越权防护**（`tools/run_host_client_demo.py` 的 [6] 段）：

- 客户端直接篡改本地 `state` 中的资金 → Host 侧数值**不受影响**；
- 客户端伪造一个不属于自己的 `RESOLVE_DECISION` → Host **拒绝**，决策保持原样；
- 客户端发送的命令里 `player_id` 会被 Host **强制覆盖**为它自己的身份，
  无法冒充房主或其他玩家。

## 7. AI 行为

启发式规则式 AI（`src/controllers/ai.py`），不涉及机器学习。

- **掷骰前**：评估是否使用道具（每回合最多 1 张），按价值优先顺序尝试。
- **买地**：综合「租金回报率、能否凑齐片区、是否高级地产、手上是否有折扣券、
  自己的资产排名」，再扣减现金安全线的惩罚项，最后与阈值比较。
  **买完可能低于安全线时会明显降低意愿**，缺钱时直接放弃。
- **升级**：按「租金提升 / 升级费用」的投资回报率打分，垄断片区优先，现金不足时收敛。
- **看守所**：关押即将到期或保释后仍高于安全线 → 付钱；
  否则掷骰赌一把（免费）。
- **道具**：缺钱用现金卡、被高租金威胁用免租卡、准备买地用折扣卡、
  有可升级地产用免费升级卡、领先者抢/停/换位、路障放在领先者前方 3 格、
  指定骰子卡会**计算每个点数落点**（无主地可买 / 自己地 / 别人高租金 / 起点 / 税收）后选最优。
- **目标选择**：优先针对总资产最高且未处于保护状态的对手。
- **难度**：简单（更保守、带随机放弃）、普通（默认）。

**实测数据**（4 人局 × 60 局）：平均每局 AI 使用道具 9.3 次、
触发机遇 53.6 次、购地 46.4 次、升级 43.1 次——说明 AI 确实在主动利用这些系统，
而不是只会点「掷骰子」。

## 13. 已知限制

1. **仅局域网**：没有公网穿透，不在同一网段无法联机（这是设计选择）。
2. **重连未做真机验证**：逻辑完整但只测了「掉线不毁局」这一段。
3. **UDP 自动发现未跨机验证**：部分企业级/校园网会屏蔽广播包，
   因此手动输入 IP 是保底方案。
4. **结算后的「再来一局」在联机模式下由房主决定**，客户端只能返回大厅。
5. **没有地图编辑器**：第二张地图需要改 `tools/gen_data.py` 并同步调整
   `board_view.py` 的网格常量。
6. **AI 随机性**：AI 决策里带少量随机扰动，观感自然但同一 seed 下不完全确定。
7. **无撤消/回放**：没有 undo，也没有对局录像回放。
8. **长时间游玩未验证**：真实窗口下自动化跑完过整局，但没有人类连续长时间试玩。

## 14. 下一步最值得做的内容

按「投入产出比」排序：

1. **跨机联机实测与防火墙引导**（最高优先级）
   在真实的两台机器 + 路由器环境下走一遍，把常见失败（防火墙、AP 隔离、
   多网卡选错 IP）的提示做得更明确。这是当前最大的未验证风险。
2. **重连真机验证**
   把「拔网线 → 插回来 → 继续玩」这条路走通，并补上客户端侧的重连 UI。
3. **AI 难度分级做细**
   目前「简单/普通」差异较小，可以引入：更具攻击性的「激进型」、
   会记牌会算概率的「精算型」。
4. **对局体验打磨**
   - 落点结算的镜头聚焦 / 高亮引导
   - 地产升级的建筑外观随等级变化（现在是圆点）
   - 结算界面的排名曲线图
5. **更多地图与内容**
   地图完全数据驱动，第二张地图（例如「海岛度假」）成本已经很低；
   机遇事件与道具卡也可以继续扩充。
6. **音效与 BGM**
   目前是程序合成的简单音效，接入合法的 CC0 音源会明显提升观感。
7. **平衡微调**
   目前 4 人局平均 128 轮、约 30 分钟，落在目标区间的偏长一侧；
   如果希望更快，可以提高 Lv2/Lv3 的租金系数并重新跑 `simulate_game.py` 验证。
