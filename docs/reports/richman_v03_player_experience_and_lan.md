# Richman v0.3 —— 玩家体验与局域网产品化交付报告

- 版本：**Richman v0.3.0**（协议版本 2，存档版本 2）
- 日期：2026-09-27
- 上一版：`v0.2.0`（`fe3bfd1`，完整游戏闭环）
- 起点确认：接手时 136 个规则测试全部通过，工作区干净

> 本报告只写**实际做过并验证过**的事情。每个模块都标了状态：
> `IMPLEMENTED`（实现了）/ `VERIFIED`（实际验证过）/
> `PARTIAL`（部分实现或部分验证）/ `NOT DONE`（未做）。
> 不使用「基本完成」「应该可以」这类表述。

## 1. v0.2 起点

v0.2 已经把「工程上能玩」这件事做完了：Host 权威、命令-事件-状态分离、
显式阶段机、可复现随机、数据驱动、交互式债务处理、抵押/赎回、
EconomyLedger、Modifier 系统、21 种道具、2 张地图、12 个角色、
LAN 双开验证 18/18、EXE 打包可启动。

但它离「像一款完成度较高的本地联机大富翁」还差一层：
**规则是对的，界面不好用**。这次接手后的第一轮审计就发现了
一个真正阻断联机的缺陷：

> 局域网界面里的 5 个输入框根本没有注册进 `widgets`，
> 因此它们看不见、点不到、打不了字 ——
> 玩家在图形界面上**无法输入房主 IP**。
> 「把 dist 文件夹发给室友，他双击 exe 输入我的 IP」这条主流程，
> 在界面上是走不通的。

这类问题的性质是「代码在跑，功能不在」。所以本轮的判断标准只有一条：
**玩家能不能看懂、能不能用、有没有被打断。**

---

## 2. 本轮目标

1. 真人游戏体验（能不能看懂现在发生了什么、下一步点什么）
2. UI / 动画 / 信息反馈
3. LAN 实际使用体验（普通玩家会不会联机）
4. 新玩家易用性（教程、图鉴、诊断）
5. 游戏节奏
6. 内容表现力（地图、角色、道具、事件）
7. 长期维护性

约束：**不推翻现有架构**，仍然是 Python + Pygame + Windows 桌面 +
单机/局域网 + Host 权威；不引入服务器、数据库、Web、账号系统、在线匹配、云存档。

`IMPLEMENTED` / `VERIFIED`

在此之前是「每个 Scene 自己画一套」：标题位置各写一个 magic number、
按钮高度各不相同、图标用文字符号（`▶` `▮` 在中文字体里没有字形，

## 5. 地图视觉改造

`IMPLEMENTED` / `VERIFIED`

v0.2 的棋盘是「方格 + 文字 + 圆点」，而且有一个真实缺陷：
`TILE_TYPE_COLORS` 里**缺少 FORTUNE / DISASTER / SHOP 三项**，
导致福运格、灾祸格、商店格全部退化成「地产蓝」——
玩家看到格子根本不知道会遇到好事还是坏事。

现在每一格的信息分层（从外到内）：

| 位置 | 含义 |
| --- | --- |
| 外缘粗色带 | **片区**（未购买也能看出属于哪一片） |
| 格内矢量图标 | **类型**：房子=地产、塔=枢纽、四叶草=福运、警告三角=灾祸、袋子=商店、%=税收、栏杆=看守所、警灯=巡查、树=公园、奖杯=奖金、旗=起点 |
| 格内文字 | 名称 + 地价（有主后改成**当前租金**，更实用） |
| 建筑图形 | **等级**：0 级空地虚框，1/2/3 层楼依次变高，金色高层是 3 级 |
| 内缘细色带 + 编号 | **所有者**（颜色 + 玩家编号，色觉差异也能分辨） |
| 斜纹 + 锁 | **已抵押** |
| 金色描边 | 该片区已被**垄断**（该区租金翻倍） |

中央区域重做：地形网格 + 城市街块景深 + 地图名水印，
再叠加「阶段胶囊 / 当前玩家卡（头像+资金+资产+地产数）/ 骰子托盘 /
最近事件条 / 奖金池 / 下一步指引」，全部不可点击，不影响棋盘点选。

## 7. 核心动画与演出

`IMPLEMENTED` / `VERIFIED`

- **骰子**：滚动 0.5～1 秒（渐慢）→ 停住显示最终点数 → 短暂停顿 → 棋子起步。
  动画时长由引擎阶段时长推导，因此引擎与画面始终同步。
- **棋子移动**：逐格插值 + 每格轻微跳跃；**每经过一格该格亮一次**
  （新增逐格反馈环），落到终点后高亮该格并显示「抵达『XX』」横幅。
- **演出队列**：新增 `src/ui/presentation.py`（`Presenter`），
  统一管理资金浮字 / 事件卡 / 横幅三类演出。
  设计约束写进了模块文档：演出**绝不参与规则**、**不阻塞引擎**、**可点击跳过**。
- 游戏节奏：设置里新增「慢 / 标准 / 快」（0.7× / 1.0× / 1.6×），
  只影响演出时长与 AI 思考展示等待，**不改变任何规则、网络 tick 或逻辑结果**。
  性能顺带修了一个真实问题：背景渐变每帧要画 900 条线，
  现在缓存复用，对局场景帧耗时 **11.5ms → 6.2ms（161 FPS）**。

## 13. 断线恢复

`IMPLEMENTED` / `VERIFIED` ← **这是 v0.2 唯一明确没验证到位的能力**

- 客户端：掉线后出现「与房主的连接已中断」弹窗，显示**正在尝试重新连接…**、
  已尝试次数、剩余秒数（倒计时）与进度条，并提供「放弃并返回主菜单」；
- 新增 `src/network/reconnect.py`（`AutoReconnector`）：每 3 秒重连一次，
  总时长与 Host 的 30 秒宽限期对齐；`GameClient.reconnect()` 现在支持重复调用；
- 房主：检测掉线 → 标记玩家 → **本局继续** → 30 秒内保持座位 →
  超时由 AI 接管 → 玩家之后重连仍能**接回控制权**（Host 摘掉 AI、恢复 RemoteController）。

验证：新增 `tools/reconnect_demo.py`（真实 TCP，同进程双端）**18/18 通过**：

```
[PASS] 客户端加入房间并获得重连凭证
[PASS] 断线前客户端能正常操作（3 次）
[PASS] Host 检测到掉线并标记玩家
[PASS] 掉线后 Host 继续推进对局（rev 12 → 13）
[PASS] 错误 token 被拒绝且给出中文提示
[PASS] 重连成功（收到 RECONNECT_OK）
[PASS] Host 清除掉线标记 / 恢复远程控制器
[PASS] 客户端追平并拿到最新快照（client rev=13 host rev=13）
[PASS] 重连后状态与 Host 完全一致（hash 一致）
[PASS] 重连后客户端能继续操作（2 次）
[PASS] 超时后由 AI 接管 / AI 接管后仍可重连接回操作
```

**仍未验证的部分**：没有物理拔过网线。上面的断开是「直接关闭 socket」，
物理断网（交换机/路由器行为、DNS/ARP 缓存、Windows 网络栈超时）只能真机覆盖。
→ 见 `docs/playtest/MANUAL_PLAYTEST_CHECKLIST.md` D 段。

## 21. 已知问题

按影响排序：

1. **6 人局偏长**（标准局约 69 分钟）。已有「快速局」（26 分钟 / 4 人）与
   「游戏节奏：快」两档缓解，但没有从规则上压缩多人局。
2. **角色网格需要滚动**：大厅与配置页的角色列表一行放不下 12 个，
   需要滚轮或翻页（当前用滚轮）。窄屏（1280×720）下尤其明显。
3. **赎回依然是「玩家专属功能」**：AI 实测仍然几乎不赎回（回本期 11 圈 >
   局均 35 圈，属理性选择），所以这个系统在 AI 对局里基本不出现。
4. **没有背景音乐**：音效是程序合成的 17 种，BGM 接口已预留，
   放入 `assets/audio/bgm_main.ogg` 即自动播放；仓库里没有合法音频资源，
   按「不引入版权风险」原则没有下载。
5. **存档没有跨版本迁移**：有 `save_version` 与版本守卫（高版本存档会明确报错），
   但没有 migrate 链。
6. **没有回放 / 撤销 / 地图编辑器**。
7. **控制台上的中文在 Git Bash 里可能显示为乱码**：
   日志文件本身是 UTF-8，游戏是窗口程序没有控制台，因此不影响玩家；
   但用 Bash 看 stdout 时会看到乱码（Windows 控制台代码页问题）。
